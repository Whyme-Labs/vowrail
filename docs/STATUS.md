## Committed

- Product requirements, security/threat model, draft negotiation profile, interface/HTTP API, competition requirements, runbook, experimental evaluation plan, architecture decisions and MIT license.
- Single-process policy gateway with a private buyer mandate, authorized 0–2 negotiation rounds, idempotency-key replay handling, minimal merchant request projection, quote validation and budget-gated checkout.
- Browser console with synthetic merchant bidding and event history. Earlier valid bids remain selectable until expiry. Credential-free offer review shows the stored price, delivery, quote expiry and budget margin; creating a Sandbox order requires a separate explicit confirmation. Above-budget quotes state the excess, and expiry updates the disabled controls without making a request.
- Explicit local simulation mode completes separate buyer approval, capture and receipt without PayPal/model adapters or credentials. Its provider and gateway journals are separate, receipts/events are labeled, stale-tab mode mismatches reject mutations, and cross-mode restore refuses startup. Default startup remains the actual Sandbox adapter. A bounded HTTP rehearsal and reusable factual demo materials accompany it; simulation does not complete real integration gates.
- A configurable buyer-side AI recommendation adapter and optional LLM-based **synthetic** merchant with seller-side price bounds. These require developer-supplied model credentials. Eight cumulative attempts include three valid Nvidia results, three truncated outputs and two earlier Google 429s; functional inference is now observed with quality limitations. Strict free-only routing is implemented; credentials stay private.
- PayPal **Sandbox-only** OAuth and Orders v2 create, approval verification and capture adapter. Actual OAuth, order creation, buyer approval, one capture and a matching completed receipt are observed. [Sanitized Sandbox proof](PAYPAL_EVIDENCE.md) records independent API and buyer-dashboard checks. Automated tests still use synthetic provider transport.
- Read-only checkout reconciliation for known order IDs; immutable capture-attempt lock, receipt/reference/amount checks, mandate expiry enforcement and buyer recovery controls.
- Dependency-free local file journal enabled by the server. Mandates, consumed rounds and replay results, locked offers, stable create/capture request IDs, order/capture references and attempted-capture locks survive process restart. Interrupted checkout requires read-only recovery; checkpoint failures and stale writers fail closed. This is local demo recovery, not a qualified hosted database.
- Unit tests for mandate/round/payment controls, concurrency, seller outputs, AI adapter and local HTTP API, plus GitHub Actions workflow.

## Known limitations

This is a single-process unauthenticated local demo. Never bind to a public interface, use production payment credentials or treat synthetic merchants as real PayPal payees. The demo's PayPal account would receive simulated purchase amounts in Sandbox only. Merchant offers are nonbinding; the model provider receives sanitized buying data when enabled but may still infer intent. No certification, universal price optimality, zero-leakage or external merchant verification is claimed.
